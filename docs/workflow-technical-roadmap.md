# 电商服饰多类图工作流技术路线

> 版本：v1.0 | 日期：2026-10-16 | 需求基准：用户本次文字描述优先，外部 Word 仅作补充

## 1. 目标链路

```text
服饰输入（二级品类）
  -> 模特（内置 / 自定义）
  -> 可选姿势参考 + 可选风格/细节参考
  -> 可选输出：平面正反 / 商品细节 / 模特上身商品特写 / 模特整套搭配展示
  -> 审核：满意 / 原提示词重生成 / 重写提示词 / 蒙版修正
  -> 下载或自定义目录导出

商标或水洗标输入
  -> OCR 与结构化校对
  -> 固定模板排版
  -> 白底洗护/成分图（不使用生成式模型绘制文字）
```

## 2. 已落地的第一批修正

- 保留数据库兼容类型 `partial` 与 `model`，但统一业务语义：
  - `partial` = 模特上身商品特写；必须重新生成，不允许从全身成图截图放大。
  - `model` = 模特上身整套搭配展示；使用项目内全部搭配单品，而非只传主商品。
- `partial` 任务现在绑定选定模特，并把模特身份参考送给 Provider。
- `model` 任务按“主商品优先、其余搭配随后”的顺序传递全套商品参考。
- 默认提示词包含完整搭配清单。上身或下装缺失时，系统会把版本化的浅石灰短款露脐运动背心 / 深灰高腰瑜伽短裤实图同时写入提示词并送给 Provider；禁止自动添加外套或饰品。
- 默认补位只进入 `partial` / `model` 模特图任务；平面图和细节图保持仅引用目标商品。完整上下装与连衣裙不补位，外套单件会补齐上下两层。
- 补位素材哈希进入任务缓存键。参考图总量按 Provider 上限裁减，真实商品优先，且为模特身份与姿势/风格保留槽位。
- 42 个二级品类的 `partial` 镜头模板已统一为模特穿搭商品特写，并要求商品参考与模特身份参考。
- 已支持项目私有的自定义模特、姿势子节点、风格参考节点和商品细节证据节点；重开项目会从 SQLite 恢复。
- 参考图角色有独立数量上限，跨项目模特 ID 会在规划入口拒绝，参考图内容哈希已进入任务缓存键。

## 3. 输入与节点数据模型

### 3.1 品类

前后端已经按“大类分组 + 叶子品类”保存和展示：

- `parent_category_id`：上装、下装、鞋履、帽饰、首饰、包袋等一级分类。
- `category_id`：衬衫、T 恤、卫衣、牛仔裤、休闲裤、棒球帽、冷帽等二级分类。
- `body_zone`、`layer_order`、`coverage_rule`：用于判断穿搭遮挡关系与缺失部位。
- 自定义品类映射到最接近的身体区域，而不是直接让模型猜。

输入节点还提供按品类筛选的结构事实编辑器。版型、领型、袖型、闭合件、口袋、腰头、下摆、图案、标识位置与独特细节由 `asset-library/structure-fields.json` 统一定义，经后端规范化后持久化。任务规划把事实作为不可擅改约束写入提示词，并纳入缓存键；QC 当前生成逐字段人工对照清单，不把颜色直方图或 ORB 相似度冒充结构语义判断。

### 3.2 中间节点

- `model`：内置模特或用户自定义模特；保存原图、许可信息、裁切预览和身份特征版本。
- `pose_reference`：模特节点的子节点，只约束姿势/构图，不复制人物和服装。
- `style_reference`：用户可添加多个；每张图必须标注角色（姿势、构图、灯光、商品细节），避免参考职责混淆。
- 对每个 Provider 建立“参考图预算”，超限时按商品权威图、模特身份、姿势、风格的优先级裁减并提示用户。

## 4. 输出与审核

四类输出必须可单独勾选。每个输出保存不可覆盖的版本链：

- 首次生成前：镜头方案可逐项使用默认提示词或填写自定义补充；选择与文本持久化，自定义内容追加在真实性/结构锁定约束之后并进入缓存键。
- 原默认提示词重生成：新建版本，输入保持不变。
- 重写提示词生成：保存基础提示词、用户补充、最终提示词与参考模式。
- 蒙版修正：以当前版本为编辑底图，同时保留原商品图作为真实性约束。
- 失败返回统一错误码：鉴权、额度、限流、超时、内容审核、Provider 不可用、输出缺失。

## 5. Provider 技术路线

Provider 层继续使用统一 `GenerateRequest`/结果/取消接口，不让节点和具体厂商耦合。

配置诊断统一收口到 `provider_diagnostics` 服务：诊断接口先读取已安全保存的配置，再进行本地文件验证或官方只读端点连通性检查，返回 `ready / warning / error` 和逐项结果。诊断请求不调用图片生成端点，`billableRequest` 固定为 `false`；无法通过只读端点证明的远端生图权限必须显示为提醒，不能伪装成已验证。

### OpenAI

- 单次生成或编辑使用官方 Images API；连续修正可使用 Responses API 的图像生成能力。
- 多参考图在适配器内显式排序，并把接口上限当作硬约束。
- API Key 使用 Windows Credential Manager / DPAPI 保存，日志永不写入完整密钥。
- 已实现官方 Images API 的文生图、多参考图编辑和蒙版提交，模型 ID 与 API 根地址可配置；当前默认模型为 `gpt-image-2.5-sunburst`，用户仍可切换其他兼容模型。

### 豆包 / 火山方舟

- 使用火山方舟官方图像生成接口和用户自己的 API Key；其官方接口支持文生图、单图和多图参考。
- 不实现静默操控消费级网页。网页方案容易被登录态、验证码、页面改版、下载策略、限流和服务条款破坏，无法作为可靠桌面软件后端。
- “免费”只作为用户账户当时可能存在的试用额度，产品不得承诺永久免费；额度不足时返回 `quota_exceeded` 并建议切换 Provider。
- 已实现 `POST /api/v3/images/generations` 适配，多参考图以 Base64 Data URL 传入，强制单图输出；当前适配器不宣称支持蒙版重绘。

### 本地生成

- 首选 ComfyUI HTTP/WebSocket API 作为本地 Provider；工作流 JSON 固定版本并随应用发布。
- 若必须对接现有 `ai.exe`，仅支持有稳定命令行参数或本地 API 的程序；子进程隐藏窗口、设置超时、捕获退出码与标准错误，并支持终止进程树。
- 本地模型下载、显存检测和授权条款独立展示，不能悄悄下载大模型。
- 已实现 ComfyUI HTTP 适配器：上传参考图、提交 API 工作流、轮询历史、读取输出并支持取消。工作流 JSON 使用 `{{PROMPT}}`、`{{NEGATIVE_PROMPT}}`、`{{SEED}}`、`{{WIDTH}}`、`{{HEIGHT}}`、`{{REFERENCE_1}}` 和 `{{MASK}}` 占位符。

## 6. 洗护与成分图

该链路采用“识别 + 校对 + 模板渲染”，不用生图模型直接画字：

1. OCR 提取商标、水洗方式、禁忌和成分百分比。
2. 规范化同义词并校验百分比合计；低置信度字段要求人工确认。
3. 图标由受控 SVG 库映射，文本用本地字体渲染。
4. 输出白底 PNG，并同时保存结构化 JSON 作为可追溯来源。

当前已完成整条链路：标签图作为项目独立素材上传，OpenAI/火山方舟 Responses API 以严格 JSON 结构提取可见文字、成分、洗护图标和置信度；低置信度与比例异常字段进入人工复核。用户确认后，后端再次校验成分与互斥规则，再用本地图标和中文字体确定性渲染 1200 × 1600 PNG。结构化 JSON、来源素材 ID 和输出文件均按项目持久化。

## 7. 示例素材审计结论

- `Model/work_library` 有 399 张商品与标签素材；`Model/work_library_plan_view` 有 399 张平面图结果。
- `总览.xlsx` 的示例图覆盖模特全身/特写、平面正反、材质细节、尺码、洗护、品牌文案和售后模块。
- 失败样例主要集中在：正反面与领型混淆、虚构纽扣/腰扣、颜色漂移、版型和袖长变化、透明材质变厚、腰头/裙摆结构错误。
- 因此 QC 应从“看起来像商品图”升级为结构字段对比：颜色、轮廓、闭合件数量、口袋、腰头、领型、袖长、图案/标识位置；高风险失败自动进入人工审核，不能自动导出。
- 第一阶段已完成：生成 `asset-library/qc-rules/reference-workbook.json`，按工作表与列语义区分正向示例、问题输出、缺陷证据、原始对照和未完成素材。48 个问题输出中有 46 个已与历史平面图文件建立可复查映射；运行时只用精确 SHA-256 拦截，感知哈希仅用于离线建表。一致性 QC 未通过或未完成的版本不能锁定或导出。
- 第二阶段已完成提示词校准配置：`example-calibration-v1` 将 179 张正向示例、48 张问题结果和 43 张缺陷证据的人工审计结论转换为四类输出的防漂移规则，重点约束反面臆造、结构/扣件/口袋变化、颜色与薄透材质变化、全身图裁切冒充特写等问题。配置证据计数由工程检查与工作簿清单强制对齐；该过程不宣称完成模型微调。
- 第三阶段已建立 `garment-authenticity-v1` 固定评测集：32 例中正负各 16 例，每例锁定工作表位置、XLSX 媒体部件和 SHA-256。自动 QC 新增前景颜色与轮廓证据；Logo、文字和扣件仍明确要求人工复核，不用通用特征匹配冒充语义识别。

## 8. 交付顺序

1. **已完成：输出语义修正**——上身商品特写、整套搭配引用、真实默认内搭素材、缺件判断、模板与 UI 命名。
2. **已完成：参考节点**——自定义模特、姿势子节点、额外参考节点、参考角色、项目隔离与数量限制。
3. **已完成：品类模型**——一级/二级品类持久化，并补齐冷帽、棒球帽、皮衣、夹克、棉服、休闲裤、西裤、领带、丝巾。
4. **已完成：洗护模块**——独立标签上传、视觉识别预填、置信度提示、人工确认、本地图标、确定性排版、项目恢复与编辑重渲染。
5. **已完成：Provider 适配、安全配置与能力门禁**——OpenAI、火山方舟、OpenRouter ICU 和 ComfyUI 支持自定义模型/地址；界面区分环境变量与 Windows 凭据保险库，声明编辑、蒙版、参考图数量和本地/云端能力，并提供单批张数、用户估价、单批费用及项目剩余预算门禁。恢复迁移会跳过不支持蒙版或超限的任务。真实账号/模型生图冒烟仍待用户配置后执行。
6. **已完成：首次生成提示词选择**——模板镜头可在生成前选择默认提示词或追加自定义要求，重开方案可恢复，最终提示词和缓存语义同步变化。
7. **进行中：质量闭环**——已完成问题样例清单、32 例固定评测集、历史平面图映射、参考图导入拦截、颜色/轮廓自动证据、Logo/扣件人工门禁、示例证据校准提示词，以及结构事实闭环；下一步用真实 Provider 输出跑固定集，按品类记录通过率、成本与重试率。
8. **已完成：人物授权、身份包与 AI 导出标识**——自定义人物必须显式选择本人/许可/同意依据后才能上传；每个自定义模特可维护正面、三分之四、侧面、背面和面部细节身份参考。导出批次固定写入逐文件来源、Provider、模型、版本和 SHA-256 的 AI 内容清单。
9. **最后执行：扩大模型与素材库**——只有真实 Provider 冒烟和固定评测集达到验收线后，才扩充模型数量与生产素材，避免把未验证差异放大。

## 9. 本阶段验收标准

- 单件上衣 + 模特：特写任务带商品、模特和深灰高腰瑜伽短裤参考；搭配展示同样补短裤，不添加外套。
- 上衣 + 裤子 + 饰品：整套搭配展示请求能收到所有项目素材，提示词逐项列出。
- 用户只勾选某一输出类型时，不创建其他类型任务。
- 同一不满意输出可产生多个版本；默认重生成与重写提示词可追溯。
- Provider 超时、取消、额度不足和审核拒绝都有明确中文状态，不吞错误。
